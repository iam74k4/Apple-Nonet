# Phase 0 技術検証の結果

- 環境: MacBook Air（M4, Mac16,12）/ macOS 26.6.2 / JIS キーボード / Xcode 27.1
- 検証アプリ: [Spikes/NonetSpike](../Spikes/NonetSpike/README.md)
- 状態: 自動で確かめられる項目は確認済み。手動テスト（T1〜T9）待ち（2026-10-30）

## 確認できたこと

| 項目 | 結果 | 根拠 |
|---|---|---|
| MultitouchSupport を読み込めるか | ○ dlopen で読める。SDK の .tbd は arm64e 向けしか無いので、直接リンクではなく dlopen にした | `--probe` |
| 接触点の構造体 | ○ 96 バイトの既知の定義で値が 0〜1 に収まる | `--probe`、ログ |
| 指の位置の取得に権限が要るか | **要らない**。アクセシビリティ・入力監視とも未許可の状態でフレームが届いた | ログ |
| 触覚のアクチュエータ | ○ 内蔵トラックパッドのアクチュエータを開ける（実際に振動するかは T6） | `--probe`、ログ |
| キーボード配列 | JIS。右⌥が無いので、既定のトリガーは右⌘にした | `KBGetLayoutType` |
| 署名 | Apple Development 証明書で署名でき、指定要件が「バンドルID＋証明書」で固定される。再ビルドしても権限が消えない | `codesign -d -r-` |
| HUD の描画 | ○ フォーカスを奪わないパネルで、モックどおりの見た目で出る | スクリーンショット |

権限が要るのはイベントタップ（トリガー検出・入力の抑止）とキー送出だけになる見込み。

## 検証アプリで仮に決めた操作

モックに無かった部分は、次のように仮決めして作った。

- **HUD を出す条件**: キーを押してから待ち時間（既定 0.3秒）以内に指を置いたら速押し扱い。指が置かれたまま待ち時間だけ止まったら HUD を出す。指を置かずに待ち時間が過ぎたときも HUD を出す
- **キャンセル**: HUD 表示中に、指を先に離してからキーを離す
- **他のキーとの同時押し**: キー（修飾キーを含む）が押されたらすぐ中断し、そのキーは前面アプリに渡す
- **連続実行**: キーを押したまま、タップするたびに実行する
- **2本指以上のタッチ**: 実行しない（2本指スワイプはページ切替用）
