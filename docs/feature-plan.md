# Nonet 機能検討

- 出典: モック `Nonet.html`（7ボード: コンセプト / HUD（動作デモ） / 設定画面 / 迷ったときだけHUD / 初回起動：自動プリセット / メニューから選ぶ設定 / アプリページと触覚）
- 状態: 検討中（2026-10-30）

## 1. コンセプト

- 一言でいうと: トリガーキーを押している間だけ、MacBook のトラックパッドが「アプリごとに変わる 3×3 のボタン」になる
- キャッチコピー: 「Stream Deckは、もう手元にある。」
- 3つの約束
  1. **買わなくていい** — 追加のデバイスは不要
  2. **覚えなくていい** — 押す前に9マスが見える。迷ったときだけ出るので、慣れても邪魔にならない
  3. **設定しなくていい** — Mac にあるアプリを見つけて最初から9マスを用意。メニューから選ぶだけで追加
- 売り方: 14日間無料トライアル → 買い切り / アカウント登録不要 / 設定データは Mac の中だけ

## 2. 基本操作

```
右⌥を押す ─┬─ 0.3秒以内にマスをタップ ─────────────→ 即実行（HUDなし）   … 慣れた人
            └─ 指を置いて止まる → 0.3秒経過で HUD 表示
                 → HUD を見ながら指でマスを選ぶ → ⌥を離して実行          … 迷ったとき
```

- トラックパッド面を 3×3 に等分し、**指の絶対位置**でマスを決める（カーソル位置は関係ない）
- HUD はトラックパッドと同じ並びの9マス。指の下にあるマスがハイライトされる

## 3. 機能一覧

優先度: **MVP** = 最初に動かす / **v1** = 販売開始までに / **後** = 販売後。「（提案）」はモックに無く、追加を提案するもの。

### 3.1 入力（トリガーとトラックパッド）

| 機能 | 内容 | 優先度 |

## 4. 技術的な前提とリスク

1. **トラックパッドの指の絶対位置（最重要）**
   - 公開 API（NSTouch）は基本的に自分のウィンドウ宛てのイベントでしか取れない。別アプリが前面にあるまま取るには、非公開の `MultitouchSupport.framework` を使うのが現実的（BetterTouchTool などと同じ方式）
   - その結果 **Mac App Store では配布できない**。Developer ID 署名＋公証＋直販になる。「買い切り・アカウント不要」の方針とは矛盾しない
2. **カーソルとクリックの抑止**: トリガー押下中に指を動かすとカーソルも動く。イベントタップでクリックを捨て、カーソルを固定できるか（`CGAssociateMouseAndMouseCursorPosition` など）を検証する
3. **触覚**: `NSHapticFeedbackManager` がバックグラウンドのアプリから効くかを検証する。効かなければ非公開 API（MultitouchSupport のアクチュエータ）を使う
4. **2本指スワイプの横取り**: Safari の「戻る」など、前面アプリに同じジェスチャーが届いてしまわないか
5. **JIS キーボードには右⌥が無い**: 日本語配列の MacBook は右側が「かな」と⌘だけ。既定のトリガーは配列を見て決める（JIS なら右⌘）。ただし ⌘英かな や Karabiner-Elements のように右⌘の単押しを使うツールとぶつかる可能性がある
6. **トリガーと他キーの同時押し**: 右⌥+E（é）や右⌘+C のような普通の組み合わせが来たら、Nonet はすぐに引っ込む。トリガーキー自体は前面アプリにも届く（例: Figma は⌥を押している間に距離を表示する）
7. **セキュア入力中は動かない**: パスワード欄にフォーカスがあるとキーを監視できない
8. **メニューの読み取り**: 対象アプリが起動している必要がある。メニュー名は言語設定で変わるので、ショートカットとメニューパスの両方を保存しておく
9. **必要な権限**: アクセシビリティ（キー送出・メニュー操作・入力の横取り）、入力監視、オートメーション（スクリプトから他アプリを操作する場合）

## 5. モックに無く、決める必要があること

1. **キャンセル操作**: HUD を出したあと、何も実行せずに抜ける方法
2. **HUD を出す条件**: モックは「指を置いて止まる」。指を置かずにキーを押し続けた場合も出すか（おすすめ: 待ち時間が過ぎたら指の有無に関係なく出す）
3. **空きマス**: アプリ別プロファイルの空きマスを、グローバルの同じ位置のマスで埋めるか、何もしないか
4. **AI アクションを何で動かすか**
   - 案A: macOS 26 の Foundation Models（端末内 LLM）。「Mac の中だけ」に合うが、Apple Intelligence 対応 Mac に限られる
   - 案B: ショートカットの「モデルを使用」アクション経由。Nonet 側の実装は最小
   - 案C: Claude などの外部 API。性能は高いが、API キーとデータ送信が必要になり、コンセプトとの調整がいる
   - モックの「レイヤーを命名」（Figma）のように外部から操作できないものは、プリセットから外す必要がある
5. **トラックパッドが無い Mac**（Mac mini / Studio＋マウス）: 対象外にするか、HUD＋マウスや数字キーで代わりに操作できるようにするか
6. **ランチャーの呼び出し方**: 専用プロファイルをどう出すか（別トリガー、トリガーの2度押し、グローバルプロファイルの1ページ目 など）
7. **対応 macOS**: おすすめは macOS 15 以降（AI 機能は 26 以降のみ）
8. **プリセットの中身の確認**: 各アプリのショートカットが実在するか（例: Xcode の Commit ⌥⌘C）、言語設定で変わらないか

## 6. 進め方の提案

- **Phase 0 技術検証（数日）**: §4 の 1〜5 を小さなサンプルで確かめる。NG が出たら操作の設計を見直す
- **Phase 1 MVP**: 入力・HUD・アプリ別プロファイル・5種のアクション・設定画面・初回起動（権限＋プリセット）・メニューバー常駐。自分で毎日使える状態
- **Phase 2 v1（販売開始）**: 触覚・メニューから割り当て・文脈変数・「試してみる」・実行フィードバック・トライアル / ライセンス・Sparkle
- **Phase 3**: ページ切替・ランチャー・AI アクション・書き出し / 読み込み

想定構成: Swift。SwiftUI（設定画面・初回起動）＋ AppKit（HUD の NSPanel、イベントタップ）。メニューバー常駐アプリで、設定は `~/Library/Application Support/Nonet/` に JSON で保存。
