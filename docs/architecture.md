# Nonet 設計

製品版 Nonet の設計と、実装の分担・決まり・仕様。機能の背景は [feature-plan.md](feature-plan.md)、実機での検証結果は [spike-results.md](spike-results.md)。

## 1. 前提

- macOS 14 以降、Apple シリコン / Intel。Xcode 27・Swift 6.4 でビルドする
- Mac App Store ではなく直販（Developer ID 署名＋公証）。非公開の `MultitouchSupport.framework` を使うため
- メニューバー常駐アプリ（`LSUIElement`）。Dock には出さない
- 設定はすべて Mac の中（`~/Library/Application Support/Nonet/`）。アカウントもサーバーも無し
- 14日間の無料試用 → 買い切りライセンス（Ed25519 署名のキーをオフラインで検証）
- アップデートは Sparkle 2

依存の向き: `NonetCore` ← `NonetPlatform`、`NonetCore` ← `NonetUI`、App はすべてに依存。`NonetUI` は `NonetPlatform` に依存しない（必要なものは `NonetServices` の protocol 経由で受け取る）。

`NonetController`（Core）が本体で、`NonetServices`（protocol の束）と `HUDPresenting`・`LicenseManager`・`HUDGuidanceStoring` を受け取って動く。テストでは偽物の実装を渡す。
- `NonetServices`: トラックパッド（`TouchSource`）・キーボードとポインタのイベントタップ（`KeyboardMonitor`。9マスを開いている間だけポインタを止め、キーが押されたら知らせる。§5 の 9）・触覚・アクションの実行・前面アプリ・メニューの読み取り・権限・インストール済みアプリ・ショートカット・AI が使えるか・ログイン項目・時計（`Scheduler`）と `presetEnvironment`（`PresetEnvironmentProviding`: この Mac でできること `PresetCapabilities` と Dock のアプリ。既定は `FixedPresetEnvironment`（どちらもできる・Dock は空）で、`live()` は `SystemPresetEnvironment`。作ったときにシェルを調べ始める。§6「プロファイルとページ」）
- `HUDGuidanceStoring`: 試用期間の残りの帯を最後に出した時刻。アプリは `UserDefaultsHUDGuidanceStore`（`com.iam74k4.Nonet.guidance.lastTrialReminder`）、テストと Debug の `--config-dir` は `MemoryHUDGuidanceStore`

## 4. 共通の決まり

- コメントと画面の文言は日本語。英語は後でローカライズする
- 画面に出る文字列は必ずローカライズ可能にする: `String(localized: "…", bundle: .module)`、SwiftUI は `Text("…", bundle: .module)`。`Localizable.xcstrings` は編集しない（統合時に抽出する）。`scripts/test.sh`（CI も）は `scripts/sync-strings.sh --check` を動かすので、カタログに無い文言や英語の訳が無い文言があるとテストが失敗する
- ログは `os.Logger(subsystem: "com.iam74k4.Nonet", category: "<担当>")`。キー入力の中身やテキストはログに残さない
- UI とサービスはメインアクター。重い処理（スクリプト・AI・`shortcuts`）は `async` でメインスレッドを止めない
- 失敗は `NonetError` で返す（`errorDescription` がそのままトーストに出る）
- 本番コードで強制アンラップ・`try!`・`fatalError` を使わない（契約のスタブを置き換えた後）
- テストは Swift Testing（`import Testing`・`@Test`・`#expect`）。`Packages/NonetKit` で `swift build` と `swift test` が通ること
- 文体はまわりのコードに合わせる。コメントは「なぜ」が必要なところだけ

## 5. 操作の仕様（セッション）

9マスはトラックパッドだけで使う。キーボードのトリガーキーも角の呼び出しも無い。トラックパッドの上の縁から1本指を下へ滑り込ませると開き（「開く」）、指を滑らせてマスを選び、マスで指を離すと実行する。外側の枠（「外枠」）まで滑らせて離すと、何もせずに閉じる。左右の外枠に指を止めると、ページが切り替わる。開いてからすべての指が離れるまでを「セッション」と呼ぶ。開く動きは `EdgeSlideRecognizer`、セッションの規則は `SessionEngine`（どちらも純粋なロジック）が持ち、`NonetController` が入出力をつなぐ。数はすべて名前の付いた定数で、なぜその値かをコードのコメントに書いている。

1. **開く**（`EdgeSlideRecognizer`）: 上の縁の帯（奥 `entryBandHeight` = 0.09、幅はすべて。トラックパッドを 1 とした割合）で触れ始めた1本指が、触れてから `entryWindow`（0.6秒）のうちに下へ `entryTravel`（0.05）以上、真下から斜めまで（|dx| ≤ `maxEntrySlope` 1.5 × dy）動いたら開く合図（`.slid`）を出す。距離は幅・奥行きをそれぞれ 1 とした割合なので、幅 15cm × 奥行き 10cm ほどの実寸では、横の動きが下の約 2.2 倍まで（水平から 24° ほどまで）開く。開きやすさ（`GlobalSettings.openSensitivity` → `EdgeSlideRecognizer.Thresholds`。控えめ 0.06・0.07・0.4 秒、標準 0.09・0.05・0.6 秒、開きやすい 0.13・0.04・1 秒。`NonetController` がフレームごとに設定から入れ、触れ始めたタッチは触れたときの決まりで見る）で帯の高さ・動き・時間が変わる。速さの条件は無い（奥の端の近くから下へポインタを動かせば、ふつうのポインタ操作でも開く）。`NonetController` は合図から `entryConfirmDelay`（0.04秒）待って開く（`pendingOpen`。フレームに頼らずタイマーで待つ）。待つ間に2本目の指が触れた・指が離れたら開かない（2本指のスクロールの2本目が遅れて触れるのを避ける）。合図は1つのタッチで1回だけ。次のときは開かない（そのタッチの間は、もう待たない）:
   - 帯の外で触れ始めた（外から帯に入ってきた指を含む）。0.6秒を過ぎた。斜めより横へ（|dx| > 1.5 × dy）0.05 以上動いた（上の縁に沿ってポインタを動かしている）
   - 2本目の指が触れた・ほかの指が触れているところに置いた・最初から2本以上で触れた
   - 接触が手のひらの大きさ（`TouchPoint.majorAxis` が `palmMajorAxis` = 25 以上。値が取れない接触は外さない）
   - セッション中に触れ始めた
2. **開いてよいか**（`NonetController.openFromEdge`）: 合図が来ても、次のときは開かない。マウスやトラックパッドのボタンが物理的に押されている（`KeyboardMonitor.isMouseButtonDown`。クリックしたままドラッグを始めるところ）・無効・アクセシビリティなし・トラックパッドなし・セキュア入力中（開くたびに確かめ直す）・設定でキーを記録中・前面アプリのプロファイルが「このアプリでは Nonet を使わない」（`Profile.mode == .off`）・Nonet のウィンドウがキー（`FrontmostAppObserving.isOwnWindowKey`。設定でマスをドラッグしている最中などでもある。ただし初回の案内の練習（`isPracticeMode`）では、案内のウィンドウの上で開く）。どれも何も知らせず、ポインタはそのまま動く（Nonet のウィンドウがキーのときだけ、起動してから最初の1回、「Nonet のウィンドウが前面のときは、9マスは開きません」のトーストを出す。設定で説明を読んですぐ試した人が、反応が無くて壊れていると思わないように。2回目からは出さない）。試用期間が終わっていたら開かず、終わったことと次にすることを失敗のトースト1つ（「試用期間が終了しました」「メニューバーの Nonet から購入・登録できます」）と `rejected` の触覚で知らせる（開く動きは1つのタッチで1回なので、トーストも1回。「このアプリでは Nonet を使わない」アプリでは知らせない）
3. **開いたとき**: ポインタの抑止を始め、ポインタを指が上の縁で触れ始めた位置に戻す（開く動きで滑らせた分だけ動いているため。`KeyboardMonitor.rememberPointerLocation()` を触れ始めたときに呼び、抑止の始まりでそこへ戻す。固定の方式は `CursorLockMethod.automatic`（移動を捨て、ずれたら戻す）に固定で、設定では選べない）。HUD をすぐに出し、軽い `activation` の触覚を鳴らす。前面アプリのページの並び（`resolvedPages`）を決め、最初のページを使う。開いた瞬間の指は、どこにあっても上の外枠にいることにする（`SessionState` の `openAnchor`。開く動きの後の 0.04 秒の待ちの間に、速く滑らせた指や「開きやすい」の指が上の段のマスに入っていても選ばない）。エンジンは「離すとやめる」の状態で始まり、そこから `SessionConfiguration.openTravel`（0.02）より滑らせてからマスを選ぶ（HUD はこの間、鍵を薄くせず「まだ何も選んでいない」見た目で出す。下の 4）。マスはポインタで選ぶ。開いている間、ポインタはふだんどおり動く（`CursorLockMethod.none`: 移動のイベントは捨てない。イベントタップで移動を捨てるとポインタそのものが止まるので、移動は前面のアプリにも届く。クリック・スクロール・ジェスチャーは捨てる。閉じても戻さない）。HUD はポインタを中心にした円で（`RadialLayout`: 半径 108pt の円の上に 8つの鍵を 45° おきに、真ん中に 9つ目。全体の皿も輪も無く、鍵ごとの暗い丸い台に白いアイコン）、マスは円の中心からのポインタの向きと距離で選ぶ（`ControllerPointerSelection` → `RadialMapper`: `HUDPresenting.show` が返す円を囲む正方形の枠（主画面の左上が原点）の中心から `KeyboardMonitor.pointerLocation` までの向きと距離をマスか外枠に変える。中心から 50pt までは中央のマス、134pt までは向きの鍵（45° ずつ。上が 1・右上が 2・右が 5・右下が 8・下が 7・左下が 6・左が 3・左上が 0）、その外は外枠。鍵の境目では角度のヒステリシス 4°、中央・鍵・外枠の境目では距離のヒステリシス 6pt で今の場所を保つ。決めたマスの中央（外枠なら奥の帯の中央、左右の外で止めていれば左右の帯の中央）の 0〜1 の座標を合成して（マスでは、鍵の中でポインタを動かした分だけ中央から最大 0.06 ずらす: `ControllerPointerSelection.cellOffset`。1pt で 0.0025。2本指から1本指に戻った後の滑らせ直し `reselectTravel` を、同じ鍵の中で 8pt ほど動かしても数えられるように。境目の帯とヒステリシスには届かない）、1本指のフレームの指の位置を置き換えてエンジンに渡すので、エンジン（`SessionEngine`・`GridMapper`）は 3×3 の座標のまま変えない。開いてからポインタが中央の外へ出るまでは、中央にいても外枠の座標を渡す（開いた瞬間に離せば必ず何もせずに閉じる。外へ出てから戻せば中央のマス）。この間は `ControllerPointerSelection.isWaitingAtCenter` → `HUDModel.isWaitingAtCenter` で、HUD は鍵を薄くせず VoiceOver にも「離すとやめる」を読まない（開くたびに薄く出ては選べないように見える）。中央から出たのにエンジンの状態が変わらなかったときも（まれ）、コントローラーが最後の状態で HUD を描き直す（`lastHUDState`）。2本以上の指（スワイプ）は実物の位置のまま。ポインタの位置が分からない実装（テストの偽物）では指の位置のまま。デモは台本の指の位置を円に写して本物のポインタを動かす（`DemoTouchSource.mapFrame`・`pointerTravel`））。HUD は開いたときのポインタが円の中心に来る場所に置く（`HUDPlacement.hudFrame(size:metrics:cursor:screen:)`。画面の端で寄せたときは、`NonetController` がポインタを中心へ動かす）
4. **9マスと外枠**: エンジンが受け取る指の位置は 0〜1 の座標で、開いている間は HUD の円の上のポインタの向きと距離から合成したもの（§5 の 3。マスならその中央、外枠なら帯の中央）。その内側の長方形を 3×3 に等分し、外側を外枠（`GridInsets.cancelFrame`: 左右 0.11・手前 0.15・奥 0.17）にする。指の場所（`GridMapper.zone`）は、最後に置いた指のマスか外枠。マスの境界にはヒステリシス 0.03、外枠と9マスの境目には `frameHysteresis` 0.015 の余裕を持たせる（トラックパッドの指で選んでいた版の名残。ポインタで選ぶ間は合成した座標がマスの中央に飛ぶので働かず、ちらつきは `RadialMapper` のヒステリシスが防ぐ）。外枠（円の外。見えない線だが、越えるとアイコンが全部薄くなる）にいる間は何も光らせず、HUD は鍵のアイコン・点・印を薄くする（台は薄くしない。`HUDView.dimsKeys` → `HUDKeyView.isDimmed`。`HUDKeyPalette.dimmedIconOpacity` 0.4、「コントラストを上げる」では 0.55。台ごと薄くすると明るい画面で白いアイコンが消え、台の下のガラスは親の不透明度で薄くならないため。開いた直後の中央はこの限りでない。文は出さない。VoiceOver に「離すとやめる」を読む）。外枠のうち真横から上下 45° まで（`RadialLayout.pagingHalfAngle`。合成した座標は `GridMapper.pagingEdge` の左右の帯）は、ページを切り替える場所も兼ねる（下の 8）
5. **触覚**: マスとマス・マスと外枠の境目をまたぐたびに `boundary`（指を置き直した・2本指から1本指に戻っただけでは鳴らさない）、ページが変わったら `pageChange`、少し長く止めるマスを止め終えたら `holdReady`、実行したら `execute`、何も実行せずに指を離したら `rejected`。設定の `haptics` はオン（`medium`）/ オフだけを選ぶ（前の版の `light`・`strong` はそのまま読む）。種類は強さと打つ回数で見分けられる（`HapticTuning`。actuationID は 弱 / 中 / 強）: `activation` 3 / 3 / 4 を1打（開いたことだけを伝える軽い1打。どの強さでも `boundary` より強くしない）、`boundary` 3 / 4 / 5 を1打、`execute` 4 / 6 / 6 を1打、`pageChange` 4 / 4 / 5 を 50ms 空けて2打、`holdReady` 4 / 5 / 6 を1打（離してよいことを知らせる。境界より1つ強い）、`rejected` はどの強さでも 3 を 40ms 空けて2打
6. **離す**（すべての指が離れたら終える）: 光っているマスに留まって1本指で離したら、HUD を閉じてそのマスを実行する（released）。留まる時間はそのマスになった時刻から数え、ふつうのマスは `liftDwell`（0.1秒。滑らせて通りかかっただけのマスを実行しないが、狙ったマスへ滑らせてそのまま離せば届く）、少し長く止めるマス（下の 7）は `holdDwell`（0.45秒）。次のときは何も実行せずに `rejected` の触覚で閉じる（cancelled。`SessionCancellation`）: 外枠で離した（`liftedInFrame`。やめる操作）・マスの境界の帯（`GridMapper.boundaryBand` 0.015。線のほぼ真上ではどちらのマスを狙ったか分からない。ただし少し長く止めるマスは、止め終えたと HUD と触覚で知らせた後なら、帯の中でも実行する）で離した（`liftedOnBoundary`）・空きマスで離した（`liftedOnEmptyCell`）・留まる時間が足りない（`liftedTooSoon`）・2本以上の指が触れたまま離した（`liftedWithSeveralFingers`）・2本指の後に残った指を滑らせずに離した（`liftedWithoutSliding`。下の 8）境目の帯は、ポインタで選ぶ間は合成した座標がマスの中央に飛ぶので入らない（`SessionHUDState.isOnBoundary` → `HUDModel.isHighlightOnBoundary` はエンジンの契約として残るが、円の HUD は描き分けない。練習の文言も境目の線とは言わない）
7. **少し長く止めてから実行するマス**（`Cell.requiresHold`。設定ファイルの名前は前の版と同じ `requiresHUD`）: 送信・録画など、間違えて実行すると困るマス。`holdDwell`（0.45秒）止めるまでは、離しても実行しない。HUD は止めている間、そのマスを白く塗らずに縁に沿って線を伸ばし（上の辺の中ほどから時計回りに一周。「視差効果を減らす」では伸ばさず点線で囲む）、止め終えたら（エンジンが `requestTick` で期限に知らせる）白く塗り、`holdReady` の触覚を鳴らす。文の案内は HUD に出さず（進み具合は縁の線が見せる）、止め終えたときに VoiceOver に「離すと実行」を読ませる（`HUDAnnouncement.holdReady`。§5 の 13）。白いマスは「いま離すと実行する」の印。HUD が止め終えたと見せたら、離せば必ず実行する（止め終えた時刻は同じ足し算で決める）
8. **ページと層**: ページは2つの層に分かれる。アプリのプロファイルのページ（アプリの層）と、グローバルのページ（グローバルの層）。前面のアプリにプロファイルが無ければグローバルの層だけ（`SessionConfiguration.layerStart` = `ControllerPresentation.globalPagesStart`。エンジンのページの番号は `resolvedPages` の通し番号のまま）。外枠のうち輪のすぐ外の帯（`RadialLayout.outerRadius` 134 から `pagingOuterRadius` 210 まで。真横から上下 45° までが左右、残りが上下。斜めは左右）にポインタを出して `edgePageDwell`（0.5秒）止めると、右なら次、左なら前のページへ（その層の中だけで輪になる: 最後のページの右は最初のページ、最初のページの左は最後のページ。`PageEdge.neighbor`。`pageChange`）、下ならグローバルの層の最初のページへ、上ならアプリの層の、下へ移る前にいたページへ（`layerChange`。強めの1打）。帯より遠く（210 より外）はどの側でもなく、止めても何も起きない（迷ったときの逃げ場。離せばどこでもやめる）。左右は止めたままなら `edgePageRepeat`（0.9秒）ごとにさらに1ページ。ただし止めたまま層のページを一回りしたら、止め始めたページの手前で待つのをやめる（輪になっても行き過ぎて見失わないため。`SessionState.pagingEdge`。帯の中で `edgeRestTravel` より動かすか、帯を出て止め直せば続きから）。ページが1つの層の左右と、もう一方の層が無い向きへは進まず、待たない（アプリの層で上、グローバルの層で下、層が1つなら上下とも）。そのうちページが1つの層の左右と、層が1つのときの上下は、帯に `edgePageDwell` 止めると、触覚は鳴らさずに、切り替える先が無いことを案内する（`SessionState.hintEdge` → `SessionHUDState.edgeHint` → `HUDModel.edgeHint`。左右は `ControllerPresentation.sidePageHint`「左右に送るページはありません」。上下は `ControllerPresentation.layerHint` で、前面のアプリにプロファイルが無ければ「このアプリのページはまだありません」、「グローバルを使う」にしていれば「このアプリはグローバルのページを使います」。層が2つでもう一方の層へ移った後の同じ向きは、案内しない）。HUD は真ん中の鍵の下に白い帯で出す。帯を出る・2本目の指で消す。帯の中で `edgeRestTravel` より動かしたら、ページの切り替えと同じく数え直す（出した案内は消さない）。開いた直後の指は上の外枠にいることにしているだけなので案内せず、`openTravel` より滑らせて動き出した時刻から数える。VoiceOver は外枠に入ったときに「離すとやめる」を読み、外枠の中で帯に入ったときは、止めると切り替わる先か案内の一言だけを読む（マスから直に帯に入ったときは「離すとやめる」に続けて読む。`HUDAnnouncement.frameAddition`）。どの側でもない外枠は、合成する位置を奥の左の角にする（`ControllerPointerSelection.gridPosition`。`GridMapper.pagingEdge` は四隅をどの側にもしない）。その側に入った・ほかの側へ移った・切り替えたときから数え直す（エンジンの `edgeRestTravel`（0.03）の数え直しは、合成した座標が帯の中央に留まるので、同じ側の外で動かしても起きない）。2本目の指が触れたら待つのをやめる。HUD は止めている間、その側の円の縁に白い矢印の円を出し、その縁に沿って線を伸ばし（「視差効果を減らす」では点線で囲むだけ）、真ん中の鍵の下にページの点を出す（`SessionHUDState.edgePaging` → `HUDModel.edgePaging`。隣のページ（端からは反対の端のページ）の端の列 `HUDModel.edgePeek` は作るが、円の HUD は描かない）。上下の帯でも同じ矢印の円をその側に出す（ページの点は左右だけで、いまの層のページだけを並べる）。ページか層が替わると、HUD は輪を押し出す（`HUDMotion`・`HUDTurnEffect`。左右も上下も同じ動きで、違うのは向きだけ: 前の輪は進む向きと反対へ 36pt、4% 縮みながら 150ms で消え、次の輪は進んだ側から 4% 大きめに 40ms 遅れて 230ms で減速しながら入る。全体 0.27 秒。「視差効果を減らす」では動かさず 0.12 秒で入れ替える。出ていく輪は `HUDStore.turn` に残し、進み具合 `turnProgress` を時間に比例して動かす。SwiftUI の transition では、向きを変えたときに出ていく輪が前の向きのまま抜けるので使わない）。層の違いは動きでは分けず、グローバルの層の台を紺に寄せ（`HUDKeyPalette.globalPlate`）、切り替えた直後だけ真ん中の鍵の下に層の題名を 1 秒出し（`HUDLayerName`）、強めの1打（`layerChange`）で知らせる。外で離せば、切り替えた後でもやめる操作のまま。2本指で横にスワイプ（2本の平均の移動が 0.12 以上）しても、その層の中で前後のページへ。縦の移動の方が大きければ層を切り替える（指を奥へ動かすとグローバルの層、手前へ動かすとアプリの層。指と中身が一緒に動く向きで、横と同じ。切り替える先が無ければ `rejected`）。指を左へ動かすと次のページ（Launchpad と同じ向き）。1回のスワイプ（2本がそろってから）で1ページ。端からは反対の端へ回る（ページが1つの層では `rejected`）。2本以上の間はハイライトしない。1本指に戻ったら残った指でまた選べるが、選んだとみなすには `reselectTravel`（0.02）以上滑らせ直す（2本の指は同時には離れにくく、残った指の下のマスを選んでいないのに実行しないため）。滑らせ直すまでは、マスを光らせず、少し長く止めるマスの進み具合も出さない（離しても実行しないため）。滑らせ直した時刻から留まる時間を数え、そこでマスを光らせる
9. **キーで閉じる**: 開いている間にキーや修飾キーが押されたら、何も実行せずに閉じる（interrupted。そのキーは前面アプリに渡す。触覚は鳴らさない）。音量・輝度などのメディアキー（system-defined のイベント）は見ない。修飾キーを離しただけ（開く前から押していたキー）では閉じない。Nonet 自身が送ったキー（`SyntheticKeyEvent.userData` の印付き・自分のプロセス）は数えない。キーボードのイベントタップは開いている間（ポインタの抑止中）だけ有効にし、開いていない間はキーボードを見ない。トラックパッドに触れていない間に届いたマウスの押す・移動・ホイールのスクロールも同じく閉じる（下の「マウスとホイール」。セッションはすべての指が離れた時点で終わるので、これが働くのは、指が離れたフレームを取りこぼしたときだけ）。`maxDuration`（20秒）を超えたセッションも閉じる（指が離れたフレームを取りこぼしたときの安全装置）。トラックパッドから続きが来なくなって、離れたことにしたフレーム（`TouchFrame.isSynthesizedLift`。下の「トラックパッド」）でも、`NonetController` がそのフレームの前に `.interrupted` を送って閉じる（光っていたマスで離したことにしない）
10. **空きマス**: `SessionConfiguration.occupiedCells`（解決したページごとの中身のあるマス）があれば、エンジンが空きマスを実行しない。無ければ `NonetController` が空きマスを無視して `rejected` を鳴らす
11. **ライセンス**: 開いている間に試用期間が終わった（まれ）ときは、HUD に「試用期間が終了しました。メニューバーの Nonet から購入・登録できます。」の帯（注意）を出し、実行の代わりに `NonetError.licenseRequired` のトーストと `rejected`。残りが `HUDGuidance.trialReminderDays`（3日）以下になったら、HUD の帯（知らせ）に「試用期間は残り N 日です」を、1日（暦の日）に1回だけ出す
12. **練習モード**: `isPracticeMode` の間は実行せず、`lastExecution` に記録だけする（`recentExecutions` には入れない）。外枠などでやめたことは練習でも `lastCancellation` に残す（初回の案内の2つ目の課題が使う）
13. **HUD の案内**: HUD はふだん文字を出さない。アイコンだけで、形があるのは光らせた鍵の下の白い円（直径 44pt）だけ。向けたまま `HUDLayout.labelDelay`（0.6 秒。離す判定の 0.1 秒と少し長く止める 0.45 秒より後）とどまると、そのアイコンの下に名前だけを白い帯で出す（`HUDView.labelCandidate`・`HUDKeyLabel`。外枠・開いた直後・空きマスでは出さず、別のアイコンへ動かすかページが替われば消して数え直す。慣れた操作では 0.6 秒以内に離すので出ない。名前を確かめたい人のためのもの）。題名もページの点もふだんは出さず、ページの点は左右の外で止めている間だけ真ん中の鍵の下に出す。円の外の帯（`HUDPillContent`: 白い不透明な面。ふだんは円の下、画面の下端で帯の分が入らなければ上。`HUDPlacement.pillFitsBelow` → `HUDStore.pillBelow`。枠（円を囲む正方形）の外に描くので、帯のために円とポインタが動くことは無い）にだけ、試用期間の注意書き（§5 の 11）と、練習中の「練習中」（`HUDAnnouncement.topNote`）を出す。少し長く止めるマスの「そのまま止めて待つ」「離すと実行」は HUD に出さず（進み具合は白い円の縁の線と `holdReady` の触覚で見せる）、VoiceOver 用の文として持つ（`HUDAnnouncement.holdWaiting`・`holdReady`。止め終えたときに「離すと実行」を読む）。「離すとやめる」「止めると次のページ」も読み上げだけ。「マスで指を離すと実行」のような操作の案内と、使い始めの案内は出さない。アイコンはどの画面の上でも暗い台に白で載せる（§7）
14. **画面に置く**: `placeWindow` のマスが光っている間（境目の帯の上を除く）、`NonetServices.windowPlacer.targetFrame(for:app:)` で置く枠を求め、`HUDPresenting.showPlacementPreview(_:)` で画面に出す（`NonetController.updatePlacementPreview`。ウインドウが無ければ枠は出さず、マスだけ光る）。ほかのマス・外枠へ移ったとき、閉じるとき（キーで閉じたときも）は `hidePlacementPreview()`。ページに `placeWindow` のマスがあれば、何に対する操作か（`HUDModel.context`: 「Safari のウインドウ」、前面のアプリが分からなければ「前面のウインドウ」。`ControllerPresentation.context(of:frontmostApp:)`）を HUD の読み上げの名前に添える（円の HUD は文を描かないので、置く枠のプレビューが何に対する操作かを見せる）。離したときの実行は §6「アクション」の「画面に置く」
15. **アイコンの見え方**: HUD の下の画面は撮らず、明るさも測らない（macOS の「画面収録」の許可は使わない）。アイコンはどの画面の上でも暗い丸い台に白で載せる（`HUDPlate`。§7）ので、明るい画面でも暗い画面でも同じ見え方になる。前の版にあった「背景に合わせて色を変える」（`adaptiveHUDInk`。開くたびに下の画面を撮って、鍵ごとに白か黒かを決めていた。画面収録の許可と、macOS 15 以降でシステムが月に一度ほど出す確認ダイアログを伴っていた）は、台を敷けば要らないので外した。設定ファイルに残っていても読み飛ばし、もう書かない（`GlobalSettings.retiredKeys`）

ポインタの抑止（`KeyboardMonitor.isSuppressingPointer`）はセッションの始めから終わりまで。セッション中に押したクリックの「離す」も、終了後に捨てる。

マウスとホイール（`TrackpadContact`・`KeyboardMonitor.isTrackpadTouched`）: `NonetController` は指のフレームから、トラックパッドに触れているかをキーボードモニターに知らせる（モニターを始めたときと、変わったとき）。抑止中に、トラックパッドに触れていない間に届いたマウスの押す（どのボタンも）・移動とドラッグ・慣性でないスクロールは、マウスやホイールのものとみなし、手を加えずに前面アプリに渡して `.interrupted` を1回送る。指が離れてから 0.5秒（`TrackpadContact.releaseGrace`。`lateClickWindow` と同じ）の間は、そのタッチの「タップでクリック」や最後の移動が遅れて届くので見分けない。慣性のスクロール（momentum phase が 0 でない）はトラックパッドのものとして捨てる。触れているかを一度も知らされていないモニターは見分けない

終わる直前の 0.5秒（`SessionEngine.lateClickWindow`）のうちに指が離れたか、触れ始めて 0.5秒たたない指がまだ触れているときは、その指の「タップでクリック」が抑止の後に届くことがある（指を離して閉じたときは、ふつうこれにあたる）。エンジンはこれを `endPointerSuppression(dropsLateClicks: true)` で知らせ、ポインタのタップは終わった後も 0.2秒（`PointerSuppressor.clickGraceInterval`）残って、その間に届いたクリックの「押す」と、対になる「離す」を捨てる（止めていたポインタの下でクリックにならないように）。移動とスクロールは渡す。0.2秒は、メインスレッドで抑止を終えた時刻から数える。
- 捨てた「押す」の「離す」が届かないとき（デバイスが外れたなど）は、押してから 2秒以上（`staleButtonAge`）たち、0.5秒ごとの見直しで2回続けて（`staleButtonSweeps`）物理的に離れて見えたら忘れる
- タップが無効にされていた間に取りこぼしたかもしれない「離す」は、最初の見直しで物理的に離れて見えたら忘れる
- macOS は Nonet が自分でタップを無効にした（`CGEvent.tapEnable(false)`）後にも `tapDisabledByUserInput` を届ける。有効にしておくつもりが無いとき（ポインタは `isPointerTapEnabled`、キーボードは `isKeyboardTapEnabled` が false）のそれは取りこぼしとみなさない（`PointerTapDisableResponse`）

実装で決めた細部（SessionEngine）:
- `NonetController` はセッションの外のフレームもすべてエンジンに渡す（エンジンの `FingerTracker` が、開いたときに触れている指を知っておくため）。エンジンはセッションの外では何も出さない
- `.open` を受けたときに指が触れていなければ（もう離れていた）、何もしない。開いている間にもう一度 `.open` を受けたら、前のセッションを interrupted で終えてから開く
- HUD の中身（`SessionHUDState`: ページ・光っているマス・外枠か・少し長く止めるマスの進み具合 `SessionHold`）が変わったときだけ `updateHUD` を出す
- 離すと同時に別の指を置いた（`FingerTracker.Change.restarted`）ときは、離したものとして終え、置いた指はセッションの外の新しいタッチにする
- `execute` の触覚はエンジンではなく `NonetController` が鳴らす（ライセンス切れ・Nonet のウィンドウ・中身の分からない空きマスでは `rejected`）

実装で決めた細部（NonetController）:
- 状態は 無効 > アクセシビリティなし > トラックパッドなし > セキュア入力中 > 動作中 の順で決める。有効な間は2秒ごとに確かめ直す。開くときにも、セキュア入力に出入りしていないかを確かめ直す（開いている間にキーで閉じられなくなるので、セキュア入力の間は開かない）
- イベントタップ（`KeyboardMonitor`）は、有効・アクセシビリティあり・トラックパッドあり のときだけ作る（キーボードのタップは作っても、開いている間しか有効にしない）
- タップの Mach ポートがシステムに無効にされた（アクセシビリティを切った など）ら `isRunning` は false になり、2秒ごとの確かめ（`startKeyboard`）で外して作り直す（2秒の間に切って入れ直しても、使えないタップを残さない。`EventTapConnection.isAlive`）。上の縁で触れ始めてから（`.touchBeganInBand`）指を離して9マスを閉じるまで、`NonetController` が `ProcessInfo` の `.latencyCritical` のアクティビティを持ち、App Nap でタイマー（開く前の待ち・止めて切り替えるまでの時間）を遅らせない（ふつうにポインタを動かすだけのタッチでは持たない）
- 指の位置（`TouchSource`）は、有効・アクセシビリティあり のときだけ読む。止めたときは、触れていた指は離れたことにする（空のフレームを渡す）。セキュア入力中と「トラックパッドなし」では止めない
- 状態が「動作中」でなくなったら、サービスを止める前にセッションを終える（ポインタの抑止・HUD が残らない）。無効にしたとき・キーの記録を始めたときも終える
- セッションの間は、開いたときの前面アプリとそのページを使い続ける（`ControllerSession`。開いた後に前面アプリや設定が変わっても、HUD のマスと実行するマスが食い違わない）
- `license.refresh()` は開いた直後ではなく、メインループの次の回で呼ぶ。呼ぶのは 60秒（`NonetController.licenseRefreshInterval`）に1回までで、ライセンスがあれば呼ばない
- 開いている間に Nonet のウィンドウがキーになったら（結果のパネルなど）、前面アプリに働きかけるマス（キー入力・スクリプト・ショートカット・メニュー項目・AI・ファイル。`ControllerExecutionPolicy.dependsOnFrontmostApp`）は実行せず、「Nonet のウィンドウが前面にあるので実行しませんでした。設定では「このマスをテスト実行」で試せます。」の失敗のトーストと `rejected` を出し、`lastExecution` に失敗として記録する。アプリを開く・URL は実行する。練習モードはこれまでどおり記録する
- 指を離してやめた（cancelled）ら、`lastCancellation`（`CancellationRecord`: 理由と日時）に残す。キー・マウス・時間切れで閉じたものは残さない
- 実行はマスで離した順に始まる。キー入力・メニュー項目・アプリ・URL・ターミナルのスクリプトは1つずつ（前の実行が終わるまで次は待つ。最長5秒）。裏で動かすスクリプト・ショートカット・AI は、前面アプリの文脈を読み終えるまでの最長1秒だけ次を待たせ、その後は並行して動く。`lastExecution` は最後に終わった実行
- 設定の変更はすぐに反映し、ファイルへの保存は 0.5 秒ごとにまとめる（`ControllerConfigurationSaver`。`stop()` で書き切る。アプリは終了するとき、`stop()` の前に設定のウィンドウの打ちかけの欄と記録中のキーを確定させる（`SettingsWindowController.commitPendingEdits()`））。書けなかったとき（ディスクがいっぱい など）は、その設定を待たせたまま 2秒後に書き直し、続けて失敗するたびに間を倍にして最長 60秒（`firstRetryInterval`・`maxRetryInterval`）。書けたら間を戻す。新しい変更が来たら、書き直しを待たずにふだんどおり 0.5秒後に書く。終了するとき（`stop()`）も書き直す。`start()` で読み込む前の変更は保存しない。設定ファイルを読めなかったときは、そのプロセスの間は保存しない（`notice` で知らせる）。壊れていたときは初期設定で置き換えて保存する
- 「このマスをテスト実行」: アプリのプロファイルならそのアプリを、グローバルなら設定を開く前に使っていたアプリを前面に出してから（0.4 秒＋最長 8×0.2 秒待つ）実行する。前面に出たとみなすのは、そのアプリが前面で、Nonet のウィンドウ（設定）がキーでなくなったとき（`NonetController.isFrontmost` は `frontmostApp.isOwnWindowKey` も見る。`frontmostApp.current` は Nonet を数えないので、設定のウィンドウがキーのままでも、そのアプリを指すことがある）。間に合わなければ、前面アプリに入力を送るアクション（キー入力・選択範囲を置き換える AI。`ControllerExecutionPolicy.sendsInputToFrontmostApp`）は実行せず、「<アプリ> が前面になりませんでした」で失敗にする（設定のウィンドウにキーを送らない）。練習モードでも実行するが、試用期間が終わっていたら実行しない
- 成功のトーストは、「実行中」のトーストを出した長く掛かるマスが終わったときだけ（いつも出す。HUD から実行したマスは HUD で見えているので出さない）。結果のパネルを出したときと失敗は別で、失敗はいつもトーストで知らせる。トーストの大きさは設定の「大きく表示」（`GlobalSettings.hudScale`: `HUDScale.standard` / `.large` = 1 / 1.25。前の版の `extraLarge` は読め、設定ではオンとして見せる。`ToastModel.scale`・`HUDModel.scale`。画面に収まらなければ ui-shell が収まるところまで小さくする）
- 長く掛かるマス（`ControllerExecutionPolicy.isLongRunning`: 裏で動くスクリプト・ショートカット・AI・ファイルの複製）が 0.5秒（`NonetController.runningToastDelay`）で終わらなければ、終わるまで「「マス」を実行中…」のトースト（`ToastModel.Style.running`。時間では消えない）を出す。終わったら、結果のパネル（トーストは消す）・失敗のトースト・成功のトーストに置き換えるか、知らせることが無ければ消す（`HUDPresenting.hideToast`。ほかのトーストに置き換わっていれば消さない）。テスト実行でも同じ（成功のトーストは出さない）
- 失敗のトーストの見出しは、どこのマスか（「プロファイル › マス」。プロファイルのページが複数なら「（2ページ目）」も）。説明は失敗の理由。表示時間は 1.5秒＋見出しと説明の1文字ごとに 0.06秒を 3〜8秒に収めたもの
- 実行の記録は `lastExecution` のほかに、新しい順に最大10個（`recentExecutions`・`recentExecutionLimit`）残す。失敗・試用期間の終了・Nonet のウィンドウで実行しなかったもの・テスト実行も含め、練習モードの記録は含めない。`ExecutionRecord.profileID` でマスのプロファイルが分かる

設定ファイル: トリガーキーで開いていた版の項目（`settings.trigger`・`fireMode`・`hudDelay`・`passTriggerToApps`・`touchActivation`）と、設定から外した項目（`autoSwitchProfiles`・`appendGlobalPages`・`showExecutionToast`・`cursorLock`。前面のアプリで切り替える・グローバルのページをつなげる・実行したことを表示はいつもオン、ポインタの固定は自動に固定）は、書いてあっても読み飛ばし、もう書かない（前の版の Nonet は、無い項目を既定値で読む）。読み飛ばした項目だけが違うファイルは、保存して失われる中身があるとはみなさない（`configuration.lossy-…` を作らない。`GlobalSettings.retiredKeys`）

実装で決めた細部（トラックパッド。`MultitouchTouchSource`）:
- 次のときにデバイスを開始し直す: IOKit の抜き差しの通知（`AppleMultitouchDevice` の match・terminate）、スリープからの復帰、ユーザーのセッションが前面に戻ったとき（ファストユーザスイッチ）、画面のスリープからの復帰、ディスプレイの構成の変化。指が触れている間は、離れるまで待つ
- ユーザーを切り替えてこのユーザーのセッションが裏に回ったら（`NSWorkspace.sessionDidResignActiveNotification`）、離れたことにする空のフレームを渡し（開いていれば何もせずに閉じる）、前面に戻るまで届いた指を捨てる（`MultitouchTouchSource.isSessionActive`。起動したときは `CGSessionCopyCurrentDictionary` の `kCGSessionOnConsoleKey` で決め、分からなければ前面とみなす）。見えない9マスを裏で開いて実行しないため
- 使えるはずのデバイスの一部を開始できなければ、1・3・10・30秒後、その後は60秒ごとに開始し直す（`MultitouchRecovery.retryDelays`）
- 抜き差しの通知を取りこぼしても気づくよう、デバイスの一覧を10秒ごとに見直し（`MultitouchRecovery.listCheckInterval`）、開始しようとしたものと違えば開始し直す
- 開始し直すときに触れていた指（`MultitouchTouchSource` の `liftFirst`）と、`TouchPipeline` が別のデバイスに切り替えるときの前のデバイスの指（`TouchDeviceSelector` の `liftPrevious`）は、離れたことにする空のフレームを渡し、`TouchFrame.isSynthesizedLift` の印を付ける（Magic Trackpad の切断・電池切れ・スリープ・別のトラックパッドへの切り替え）。`NonetController` はそのフレームの前に `.interrupted` を送るので、開いていれば光っているマスを実行せずに閉じる（§5 の 9）。`TouchFrameCoalescer` はこのフレームを後のフレームで置き換えない
- フレームが届かないまま止まったデバイスを、トリガーを押したときに開始し直す仕組み（`revalidate`）は、トリガーキーと一緒に外した（利用者がこれから触れるという合図が無くなったため）

## 6. 機能の仕様

### プロファイルとページ
- グローバルが必ず1つ（先頭）。アプリのプロファイルは bundleID ごとに1つまで。各プロファイル 1〜3 ページ
- アプリのプロファイルの使い方は `Profile.mode`: `profile`（このプロファイル）・`global`（グローバルを使う。ボタンは残す）・`off`（このアプリでは Nonet を使わない。§5 の 1）。`isEnabled` は `mode == .profile` の計算プロパティ（false を入れると `global`）。`setAppMode(_:for:preset:)` はプロファイルが無ければ（preset があればその中身で）作ってから変える
- `resolvedPages(frontmostBundleID:)`: そのアプリのプロファイルが `profile` なら、そのページの後ろにグローバルのページをつなげたもの（いつも前面のアプリで切り替え、いつもつなげる。HUD では2つの層に分け、下の帯でグローバルの層へ移る。§5 の 8）。プロファイルが無い・`global` ならグローバルのページだけ。`ResolvedPage.title` は HUD の題名で、ページに名前（`Page.name`）があれば「Xcode · デバッグ」、無ければプロファイルの名前
- グローバルの初期値は、1ページ目が「画面に置く」の9マス（`PresetLibrary.makeWindowPlacementPage()`。`WindowRegion.allCases` の順で、名前は場所の名前、アイコンは `WindowRegion.symbol`）、その後ろがランチャー（`NonetConfiguration.initial(appPresets:installedBundleIDs:dockApps:)`。`PresetLibrary.makeGlobalProfile(installedBundleIDs:dockApps:)` の先頭2ページ。候補が無ければ「画面に置く」だけ）: Dock の persistent-apps（`com.apple.dock` の CFPreferences を読むだけ。インストールされていないものと Nonet は飛ばす）を Dock の順に先に、残りを `PresetLibrary.launcherCandidates` のうちインストール済みのアプリを候補の順に、最大2ページ（18個）（起動アクション、アイコンはアプリ）。Dock にもある候補は候補の短い名前（「VS Code」など）を使い、ChatGPT は1つだけ。Dock を読めなければ候補だけ。macOS 26 で Launchpad が無くなったので、その代わりになる。Arc は 2026-12-22 に動かなくなるため、候補には Dia を入れている（Arc のアプリ用プリセットは残す）
- Electron 製の VS Code と Cursor は `kAXDocumentAttribute` を出さず（`AXUIElementCopyAttributeValue` が -25205）、ウインドウの `kAXTitleAttribute` も「Code」だけなので（2026-11-01 に VS Code で確認）、これらの前では `NONET_DOCUMENT_PATH`・`PROJECT_DIR` が空になり、プリセットの Claude Code はホームで開く。利用ガイドにその旨を書いてある。題名からの推定は、題名が無いのでできない
- プリセットはこの Mac でできること（`PresetCapabilities`: Apple Intelligence・`claude` コマンド）に合わせて組み立てる（`PresetLibrary.apps(for:)`・`preset(forBundleID:capabilities:)`。引数の無い呼び出しは「どちらも使える」）。AI が使えなければ AI のマスを入れず、外側のマスを1つ中央に移す（Safari・Chrome・Arc はページ内検索 ⌘F、Mail はアーカイブ、Teams はミュート、Slack は会話へ移動 ⌘K、Notion は検索、メモはチェックリスト。移した元の位置には、AI を使える Mac には無い別のマスを入れて9マスのままにする（`aiCentered` の `filler`: Slack は前の未読、Teams は挙手、Mail はフラグ、Safari と Chrome は新規ウインドウ、Arc はサイドバー、Notion は新規ウインドウ、メモは新規フォルダ））。Claude Code のマスはどの場合も中央に置かない（Xcode はクイックオープン ⇧⌘O、VS Code・Cursor はコマンド ⇧⌘P、ターミナルは新規タブ ⌘T を中央に置き、Claude Code はその外側。`claude` が無ければ空ける）。Apple Intelligence のモデルをダウンロード中なら使えるものとして扱う。分類の説明（「〜など%lld個」）は入っているマスだけを数える
- 初回の設定（`NonetConfiguration.initial(…, dockApps:)`。インストール済みでプリセットのあるアプリすべてのプロファイルと、グローバルのランチャーを入れる）と「プロファイルを追加」は、`NonetServices.presetEnvironment` の `capabilities` と `dockApps()` を使う。`claude` はシェルを調べ終えるまで見つからない扱いなので、初回の設定は調べ終える前にわかっていることで作り（`claude` がまだ分からなければ Claude Code のマスは入らない）、調べ終えたら（数秒）できることが変わっていて、それまでにプロファイルを何も変えていなければ、プリセットのプロファイルを作り直す（全体の設定はそのまま。`NonetController.rebuildFirstPresetsWhenResolved`。プロファイルが変わっていれば作り直さない）

### 設定ファイル（`ConfigurationStore`）
- `~/Library/Application Support/Nonet/configuration.json`（`NonetConfiguration`: `version`・`settings`・`profiles`）。書き込みはアトミックで、中身が変わるときだけ書き、直前の版を `configuration.backup.json` に残す。読めない今のファイルは上書きしない
- 書式は前の版の Nonet でも読めるようにする。無い項目・知らない値は既定値で読み（`decodeLossy`）、新しい項目は既定値と違うときだけ書く:
  - `settings.hudScale`（`standard` | `large`。前の版の `extraLarge` も読む）は `standard` 以外のときだけ書く。使わなくなった前の版の項目（`GlobalSettings.retiredKeys`）は読み飛ばし、もう書かない（§5 の終わりの「設定ファイル」）
  - `Profile.mode`（`profile` | `global` | `off`）: `isEnabled` はいつも書き（`profile` のときだけ true）、`"mode": "off"` は `off` のときだけ足す（前の版は使わないアプリを「グローバルを使う」として読む）。知らない `mode` は `isEnabled` で読む
  - `Page.name` は付けたときだけ書く（改行は空白にし、空なら無し）
  - 前の版の `ScriptAction.output`・`ShortcutAction.output` は読み飛ばす（出力は空でなければ結果のパネルに出す）。前の版の `sharedCells`（共通マス）も読まない（原本は `configuration.lossy-…` に残る）
- 控え（`ConfigurationBackup`）: `Backups/configuration-<UTC の yyyyMMdd'T'HHmmss'Z'>-<理由>.json`（中身は configuration.json と同じ書式）を新しいものから10個（`maxBackups`）残す。理由は `auto`（`save()` で、いちばん新しい控えから1時間（`automaticBackupInterval`）たっていれば、変える前の設定）・`delete-profile`・`delete-page`（マスのあるページだけ）・`import`・`reset-profile`・`restore`（以前の設定に戻す前）。設定の「以前の設定に戻す…」が並べて読む。同じ秒の控えは、理由が違っても続けて番号を付け（`-2`・`-3`…。番号の無いものは 1。`parseBackupName`）、日時 → 番号 → 名前の順で新しいものから並べる（同じ中身の控えを作らない確かめと、10個への間引きが、本当にいちばん新しいものと比べるように）

選択中のテキストはアクセシビリティ API（`kAXSelectedTextAttribute`）で取り、取れなければ ⌘C でクリップボード経由（クリップボードは元に戻す）。何も選択していないと ⌘C で行を丸ごとコピーするエディタ（VS Code 系・Cursor・Windsurf・Obsidian・JetBrains の IDE・Android Studio・Sublime Text）で、改行（LF か CRLF）で終わる1行だけが取れたときは、選択なしとみなす。書類の場所は前面ウィンドウの `kAXDocumentAttribute`、ブラウザの URL は Safari / Chrome / Arc / Edge / Brave に AppleScript で聞く。

スクリプトには、変数ごとに要るものだけを読んで渡す。`NONET_SELECTED_TEXT`（⌘C を送ることがある）と `NONET_BROWSER_URL`（初回はオートメーションの確認が出る）は、スクリプトのソースにその名前が書かれているときだけ読む（コメントでもよい。別のファイルのスクリプトを呼ぶだけなら、名前をコメントに書いてもらう）。ほかのスクリプトは ⌘C を送らず、ブラウザにも聞かない。`NONET_APP_BUNDLE_ID`・`NONET_APP_NAME`・`NONET_DOCUMENT_PATH`・`NONET_PROJECT_DIR`・`PROJECT_DIR` は副作用が無いので、値があればいつも渡す。

プロジェクトのフォルダ（`ScriptLocation`）: `.xcodeproj` などの書類はその親、ほかは上へたどって `.git` か `Package.swift` のあるフォルダ。ホームの中ではホームで止まり、深さの制限は無い（Maven・Gradle・Android や深いモノレポ）。ホームの外（`/Volumes/SSD` など）では、書類のフォルダを含めて上へ32個（`maxSearchLevels`）までで、`/` や `/Volumes` のような浅いフォルダは調べない。ネットワークの場所の書類では探さず、書類のフォルダをそのまま使う。調べるのはメインスレッドの外で、0.3秒（`ScriptLocation.timeout`）で終わらなければ（眠った NAS など）プロジェクトのフォルダは無しで、作業フォルダはホーム。

クリップボード（`NonetPlatform/Actions/Pasteboard.swift`）:
- 中身はメインスレッドの外で、Carbon の Pasteboard Manager を使って1本の直列のキューで1つずつ読む（`PasteboardReader`・`CarbonPasteboard`）。`NSPasteboard(name:)` はいつも同じ共有のオブジェクトを返してスレッドセーフではないので、`NSPasteboard` はメインスレッドでだけ使う。前の読み取りが時間切れの後も続いていれば、新しく読み始めない
- Nonet がクリップボードを一時的に使う操作（⌘C で読む・⌘V で貼る）は1つずつ行う（`ClipboardSession`）。まだ戻していない貼り付けの写しは、次の操作が写す前に戻す
- 写せないとき（64 MB より大きい・ファイルの約束・読む許可が無い・元のアプリが時間内に渡さない）はクリップボードに触らない。⌘C は送らず、「選択範囲を置き換える」は結果のパネルに出す。制限時間は1秒、読む前に macOS が確かめることがある（macOS 15.4 以降。`PasteboardAccess.asks`）ときは利用者が答えるまで最長20秒。「常に拒否」なら読みも戻しもしない
- 画像は項目ごとに1つの形だけを写し、Finder のファイルの項目ではアイコンを写さない（どちらも求められてから作るので遅く大きい）
- パスワード管理アプリの印（`org.nspasteboard.ConcealedType`）があれば、読みも戻しもしない。貼り付ける結果には、履歴のアプリに残さない印（`org.nspasteboard.TransientType`）を付ける
- ⌘C の後に何も書かれなければ、遅れて書くアプリのために0.5秒だけ見張り、最初に書かれたものを、⌘C を送ったアプリがまだ前面のときだけ元に戻す。ほかの操作や書き込みが始まったらやめる（利用者が自分でしたコピーは戻さない）

### ウインドウとメインメニュー（ui-shell）
- 画面には出ないメインメニュー（`ShellMainMenu`。App が起動時に `NSApp.mainMenu` に入れる）を持つ。Nonet は `.accessory` なのでメニューは見えないが、設定や初回の案内のウインドウがキーの間、標準のキーがこれを通って文字の欄やウインドウに届く（無いとライセンスキーの欄に ⌘V で貼れない）。アプリのメニュー: 「Nonet について」（設定の「Nonet」のタブ）・「設定…」⌘,・「終了」⌘Q。編集: 取り消す・やり直す・カット・コピー・ペースト・ペーストしてスタイルを合わせる・削除・すべてを選択。ウインドウ: 閉じる ⌘W・しまう ⌘M。ヘルプ: 「Nonet ヘルプ」⌘?（利用ガイドを開く。英語で動いていれば英語のページ）。設定のウインドウは ⌘W のために閉じられるウインドウにしておく
- ⌘Q は、Nonet のウインドウが前面のときは Nonet を終了する。ほかのアプリが前面のまま結果のパネルをクリックしてキーにしたときの ⌘Q は、パネルだけを閉じる（メニューバーは前面のアプリのものなので、Nonet を終わらせない）
- Nonet の最後のウインドウ（設定・初回の案内）を閉じたら、その前に使っていたアプリを前面に戻す（Nonet が前面のままキーのウインドウが無いと、キー入力のマスのキーが Nonet に送られ、どこにも届かない）

### HUD（ui-shell）
- HUD は全体の面を持たない: 皿も輪も無く、ポインタを中心にした円の上に鍵を並べる（`HUDView`・`HUDKeyView`。寸法は `HUDLayout`・`RadialLayout`。§5 の 3・13）。鍵ごとに暗い丸い台（`HUDPlate`。直径 36。白の量 0.1 の色を重ねた面に、細い明るい縁と薄い影）を敷き、その上に白いアイコンを載せる。台の描き方は `HUDPlateStyle`: macOS 26 以降は下に `.clear` の Liquid Glass を敷いて下の画面をぼかし、面の不透明度は 0.68（`.regular` は下地に合わせて明るくも暗くもなり、台ごとに濃さが揃わないので使わない。9つのガラスは `HUDGlassGroup`（`GlassEffectContainer`、spacing 0）でまとめて描く）。それより前の macOS はぼかせないので 0.8。「コントラストを上げる」では 0.85。「透明度を下げる」ではガラスを敷かず不透明にする（`HUDStore.reduceTransparency`。HUD を出すたびに読み直す）。暗さは上に塗る面だけで決まり、真っ白な画面の上でも白いアイコンとの比が 4.5:1 以上（0.68 で約 6:1、0.8 で約 9:1、0.85 で約 11:1）あるので、下の画面の明るさを問わず同じ見え方になる。HUD は開いたときのポインタが円の中心に来る場所に置く（`HUDPlacement.hudFrame(size:metrics:cursor:screen:)`。枠は円を囲む正方形 268×268（倍率 1）。画面の使える範囲（端の余白 8）に収める。置く場所の設定は無い）。`HUDPresenting.show` が場所を決めて円を囲む正方形の枠（`HUDPlacement.mapFrame`。主画面の左上が原点）を返す。開いたときのポインタが円の中心に無ければ（画面の端で枠を寄せた）、コントローラーが一度だけポインタをそこへ動かす（`ControllerPointerSelection.startPoint` → `KeyboardMonitor.movePointer`）。枠の大きさは帯・ページ・外枠で変わらない（`HUDLayout.size(for:)` は円だけ。帯は枠の外に描く。§5 の 13）。パネルは枠の周りに `HUDLayout.shadowMargin`（40）の余白を持ち、そこに帯とその影・白い円の光・台の影を描く。光らせた鍵は白い円（直径 44。明るい画面で台の並びの穴に見えないよう、細い暗い縁を付ける）に濃いアイコン。空きマスは小さな台（直径 12）に白い点、光らせると白い円と同じ大きさの台に白い点線。少し長く止めるマスは右上に、小さな台に載せた白い印（`HoldMark`）を付け、止めている間は台を白い円と同じ大きさにして、その縁から少し内側（`HUDMetrics.ringInset`）に白い線を伸ばす（§5 の 7。線の外側にも台の暗さが残るので、明るい画面でも線が溶けない）。外枠の帯（上下左右）で止めている間は、その側の円の縁に白い矢印の円と進み具合、左右なら真ん中の鍵の下にいまの層のページの点。ページか層が替わると輪を押し出し、グローバルの層では台を紺に寄せる（§5 の 8）。指の点は描かない（`SessionEffect.fingerMoved` は HUD に渡さない）。「画面に置く」のマスを光らせている間は、HUD の1つ下の階層のパネル（`HUDPlacementPreviewController`。`HUDWindowController.showPlacementPreview`）で、置く枠を薄い青の面と線で画面に出し、左上に「離すと、ここに置きます」を添える（§5 の 14）。結果のパネルは HUD を出していた場所（無ければポインタ）に出す。トーストだけは面を持つ（`HUDSurface`: macOS 26 以降は Liquid Glass で文字は階層のスタイル、それより前はモックどおりの暗い不透明な面 `HUDPalette`・`HUDColors`。「透明度を下げる」では不透明な面）
- 文字は 4.5:1・点は 3:1 以上（説明と二次の文字 #9A9A9A、選んでいない点 #777）。「コントラストを上げる」では縁・空きマスの縁（ふだんは付けない）・文字を明るくする（HUD やトーストを出すたびに読む）
- 「大きく表示」（`hudScale`: オンで `large` = 1.25 倍。前の版で選べた `extraLarge`（1.5 倍）は読んだまま使い、スイッチはオンに見える。`HUDModel.scale`・`ToastModel.scale`）で HUD とトーストを大きくし、画面に収まらなければ収まるところまで縮める
- 前面アプリからフォーカスを奪わない非アクティブなパネル。全 Space・フルスクリーンの上にも出す。表示先はポインタのあるディスプレイ
- トーストは画面下部に 0.8 秒。失敗は 1.5秒＋見出しと説明の1文字ごとに 0.06秒（3〜8秒）。実行中のトースト（`ToastModel.Style.running`。くるくる回る印）は時間では消えず、`HUDPresenting.hideToast` か次のトーストで消える
- 結果のパネル（`showResult`）: AI の結果など。文を選択でき、「コピー」「閉じる」と Esc で閉じる。前面アプリのフォーカスは奪わない

### ライセンス（keys-license）
- 試用は初回起動から14日。残り日数は日付の切り上げ。`LicenseManager.trialEndDate`（試用中だけ）は最後に数えた時刻＋（14日 − 使った時間）で、時計を変えない限り毎回同じ日時になる（ライセンスのタブの「11月14日まで」）
- `LicenseManager.registeredLicenseKey`（登録済みのときだけ）は保存したキー。設定の「キーをコピー」が、同じ人のほかの Mac に登録するために使う。ライセンスは1人に1つで、その人が使うすべての Mac で使える（台数の登録や解除は無い）
- キーは `base64url(JSON).base64url(署名)`。JSON は `LicenseInfo`。公開鍵は Info.plist の `NonetLicensePublicKey`
- `nonet-license keygen` で鍵を作り、秘密鍵はリポジトリの外に置く。`issue` は発行したキーを `Config/Nonet.xcconfig` の `NONET_LICENSE_PUBLIC_KEY`（アプリに入る公開鍵。`//` で切れていれば止まる）と秘密鍵の隣の公開鍵（または `--public`）で検証してから出す。`--public` がアプリの公開鍵と違えば、`--skip-app-key-check` が無い限り出さない
- 貼り付けたキーは、空白・改行を除いた全体が `eyJ` で始まるキーの形ならそれを使う。そうでなければ前後の文（「License key:」「License Key」（改行）・引用符・メールの「>」・句点など）を除いて、キーの形（`eyJ…` と 86 文字の署名）の部分を探し、中身が `LicenseInfo` として読めるものがちょうど1種類あるとき（読めるものが無ければ、キーの形のものがちょうど1種類あるとき）だけそれを使う（`LicenseCoding.licenseKey(in:)`）。保存するのはキーの部分だけ
- 試用は使った時間を数える（時計を戻しても増えない）。`canExecuteActions` はいつでも正しいが、表示用の `entitlement` は `refresh()` でしか変わらない。`NonetController` は9マスを閉じた後（60秒に1回まで。開いている間の最初のフレームでファイルを読み書きしない。ライセンスがあれば呼ばない。§5）と、試用中の表示のまま試用期間が終わっていて開かなかったとき（一日の途中で終わったとき。「試用期間が終わりました」のウィンドウをすぐ出す）、ui-shell はメニューを開いたとき・スリープ解除・日付の変化・時計の変更で `refresh()` を呼ぶ。ライセンスが登録されているときの `refresh()` は、試用の記録を書かない
- 試用の記録（開始日・最後に数えた時刻・使った時間）は `UserDefaultsLicenseStorage` が UserDefaults と `Application Support/Nonet/` の隠しファイルに置き、アプリ本体（`UserDefaultsLicenseStorage(keychain: SystemTrialRecordKeychain(), marker: SystemTrialRecordKeychain.machineMarker(), evidence: FileTrialUsageEvidence.standard())`）では `SystemTrialRecordKeychain`（ログインキーチェーンの汎用パスワード `com.iam74k4.Nonet.license.trial`。Developer ID で署名した製品版でだけ動く）にも置く。キーチェーンは起動ごとに1回読み（ロックされているなどで読めなければ `TrialRecordReading.unavailable`。数えるたびに読み直し、読めるまではその項目に書かない。読んでいない前の記録を上書きしないため）、ほかの2か所の両方に (時刻, 使った時間) の組が無ければその組で、あれば使った時間だけを下限として数える。書くのは起動したとき・使った時間が1時間増えたとき・時計が変わったとき（`didSaveTrialProgress`・`needsKeychainWrite`）。`--self-check` と Debug の `--config-dir` はキーチェーンを使わない
- 2つ目のキーチェーンの項目（`marker`。`SystemTrialRecordKeychain.machineMarker()`）: サービスの名前は SHA-256(IOPlatformUUID の大文字 + 改行 + bundle ID の小文字) の16進64桁、アカウントはその先頭16文字、ラベルは付けない（名前から Nonet のものとは分からない）。1つ目と同じ記録を同じときに書き（`didSaveTrialProgress`）、起動ごとに1回、1つ目と一緒に読んで `TrialRecord.reconciled` でまとめる。1つ目だけを消しても試用は続く。Mac の識別子は IOKit（`IOPlatformExpertDevice` の `kIOPlatformUUIDKey`）で読み、読めなければ使わない。識別子そのものは保存しない。動くのは1つ目と同じく Developer ID で署名した製品版だけ
- 以前に使った跡（`evidence`。`TrialUsageEvidence`・`FileTrialUsageEvidence`）: 4か所のどこにも開始日が無いときだけ、`UserDefaultsLicenseStorage.earlierUseStart` で開始日を決める。2つ目の項目があるのに記録として読めなければ（壊れている・書き換えられた）、いつ使ったかは分からないので、ちょうど期限切れになる日（今 − 14日）。そうでなければ `Application Support/Nonet/Backups/` と `~/Library/Caches/<bundle ID>/` のフォルダの作成日のうちいちばん古いもの（フォルダは中身を書き換えても作成日が変わらず、試用はそれより前に始まっているので、実際より長くは数えない。初めての起動でフォルダが先にできても、作成日はほぼ今なので試用は減らない）。`earliestPlausibleUse`（2025-01-01）より前の日付は使わず、今より後の日付は今にする。フォルダの日付は署名に関係なく見る。`--self-check` と Debug の `--config-dir` は、2つ目の項目もフォルダも使わない
- 無効にしたライセンス（`LicenseRevocationList`。`LicenseRevocation.swift`）: 返金したキーや公開されてしまったキーのライセンス ID の SHA-256（16進の小文字）を、`NonetCore/Resources/RevokedLicenses.txt`（1行に1つ。`#` から後ろはコメント）としてアプリに入れる（`LicenseRevocationList.bundled`。読めなければ空にしてログに残す）。`LicenseManager` は保存したキー（`storedLicense()`）と登録しようとしたキー（`verify(licenseKey:)`）の両方を、署名を確かめた後に照らし、一覧にあれば `LicenseError.revoked`。保存したキーなら登録していないものとして扱い（試用の記録で数え直す）、キーは消さずに `revokedLicense` に中身を入れ、設定のライセンスのタブが理由を出す。一覧に足すのは `nonet-license revoke`（[release.md](release.md) 3.5）。通信はしない。`nonet-license verify` は一覧を見ない
- NonetCore は Foundation と Observation と CryptoKit だけ（§2。CryptoKit は、`License.swift` の署名の確かめと `LicenseRevocation.swift`・`TrialRecordKeychain.swift` の SHA-256 に使う）だが、`Licensing/TrialRecordKeychain.swift` だけは例外として Security・LocalAuthentication・IOKit を使う（キーチェーンの読み書きと署名の身元の確認、2つ目の項目の名前に使う Mac の識別子の読み取り。`TrialRecordKeychain` の protocol で差し替えられ、テストでは本物のキーチェーンに触れない）。ライセンスのロジックと同じ場所に置き、App が1行で使えるようにするため
- 置き場所の記録が食い違ったら `TrialRecord.reconciled` でまとめる: 開始日は最も早いもの、(最後に数えた時刻, 使った時間) は置き場所ごとの組として、次に数えたときに最も多くなる組 (U, V + U)（U = 使った時間の最大、V = 時刻 − 使った時間 の最小）にする。古い記録（バックアップから戻したフォルダ・書けないファイル）で同じ時間を二重に数えず、1か所だけ書き換えても延びず、時計を戻しても減らない
- 動いている間に、保存先の使った時間が自分の数えた量より多くなっていたら（ほかの Nonet が数えた）、自分の数え方（自分の使った時間 ＋ 前に数えてからの経過）と保存先の数え方（保存先の使った時間 ＋ 保存先の最後に数えた時刻からの経過）の多い方を取る。使った時間を最も多く残し、同じ経過を二重には数えない（保存先の量に自分の経過を足さない）

### 起動オプション（App/main.swift・`ShellLaunchOptions`）
- `--self-check`（すべてのビルド）: 画面もイベントタップも作らずに、プリセット・ランチャーの候補・設定の保存と読み直し・MultitouchSupport の読み込みを確かめ、JSON を出して終わる（失敗なら終了コード 1）。試用の記録は UserDefaults と Application Support の写し（`.install`・`.install-seen`・`.install-used`）の両方から読むだけで（`ShellSelfCheck.LicenseSnapshot`）、アプリと同じく試用に厳しい方を使うので、アプリと同じライセンスの状態を出す。ただしキーチェーン（2つの項目）と以前に使った跡（フォルダの作成日）は使わないので、UserDefaults と Application Support の記録がどちらも消えているときは、アプリが期限切れとしても「残り14日」と出ることがある。試用を始めたり、数えたり、記録をそろえたり書いたりはしない。`scripts/test.sh` が最後に動かす
- Debug ビルドだけ: `--config-dir <dir>`（設定をそのフォルダに置き、ライセンスはメモリだけに置く。試用期間の知らせの日付（`MemoryHUDGuidanceStore`）・「今後表示しない」・試用期間の終了のウインドウを出した日も UserDefaults に書かない。下の「同時に1つだけ」も調べないので、インストールした Nonet と並べて動かせる）・`--show-settings [tab]`・`--show-onboarding`・`--onboarding-step <welcome|practice>`・`--preview-hud`・`--preview-toast`・`--preview-result`・`--simulate-expired-trial`・`--snapshot <dir>`（開いたウインドウを画像に書き出して終わる）・`--demo`（販売ページ用のデモ動画: 本物の操作のロジックと HUD で何も実行せず、指の位置を示すトラックパッドの図を出す。`--demo-app <bundle ID>`（前面のアプリの代わりにこのプロファイル）・`--demo-backdrop <画像>`（必須。`scripts/make-backdrop.swift` の共通の背景。無い・画面と縦横比が違うときは始めずに終える）・`--demo-script`（`DemoScript` の台本どおりの指の動きを入れ、終わったら終える）・`--demo-start-file <パス>`（このファイルができてから始め、消えるまで待つ）。App/DemoMode.swift）。画面の確認用

### 起動の順と、同時に1つだけ（App/main.swift・App/SingleInstance.swift・`ShellInstanceGuard`）
同じ Nonet が2つ動くと、どちらもトラックパッドを見て、1回の操作でマスが2回実行され、試用の時間も2倍に数えられる。
- `main.swift` は `--self-check` を見た後、NSApplication を動かす前に `SingleInstance` で同じ bundle ID の Nonet を調べる
- 終わり始めた Nonet は `applicationWillTerminate` で一時フォルダに印のファイル（`ShellQuitMarker`。`Nonet-quitting-<プロセス番号>`）を書き、起動したときに消す。印のあるもの（終了した直後に開き直した・Sparkle のアップデートの後の再起動など）は残す候補にせず、終わるのを最長10秒（`takeOverTimeout`）待ってから起動する（2つが同時にトラックパッドを見ないように）
- どのプロセスから見ても同じ決め方で、残りの中から残す1つを決める（`ShellInstanceGuard.keeper`）。まず場所ごとに（本来の場所 = ディスクイメージや App Translocation でないもの・一時的な場所）1つずつ候補を、起動し終えたもの → 先に開かれたもの → プロセス番号の小さいもの の順で選ぶ。次に、本来の場所の候補を残す。ただし一時的な場所の候補の方がビルド番号（`CFBundleVersion`。`App/SingleInstance.swift` が各プロセスの `Contents/Info.plist` から読む）が数として大きければ、そちらを残す（分からなければ新しいとはみなさない）。2段に分けるのは、2つずつ比べる順に「場所が違えばビルド番号」を混ぜると、3つ以上のときに順が輪になり、プロセスごとに答えが変わることがあるため
- 残すのがほかのもので、それが起動し終えていれば、待たずに任せて終わる（もう一度開くとすぐに設定が開くように。相手の `applicationShouldHandleReopen` が設定のプロファイルのタブを開く）。一時的な場所から開いた自分が本来の場所のものに任せるとき（ディスクイメージの方が新しくない）は、黙って終わらずに「Nonet はすでに動いています」（`ShellMoveToApplications.explainAlreadyRunning`。両方の版を言い、入れ替えるには動いている方を終了してから開き直すと伝える）を出してから任せる（`ShellInstanceDecision.explainAndHandOff`）。相手も起動の途中（同時に開かれた）なら最長3秒（`shutdownGrace`）待ってから任せる
- 残すのが自分で、起動し終えたほかの Nonet が動いていれば（自分がアプリケーションフォルダなどのものなら、ディスクイメージなどから開いたもの。自分が新しいディスクイメージのものなら、古いアプリケーションフォルダのもの）、それに終わってもらってから代わりに動く（`replace`）。10秒（`takeOverTimeout`）たっても終わらなければ、こちらが譲る。新しいディスクイメージの方が動いたときは、起動した後で `AppDelegate` がアプリケーションフォルダの Nonet を置き換えるかを尋ねる（下の「アプリケーションフォルダへ移す」）
- 同時に2つ開かれても、残るのはちょうど1つ

### アプリケーションフォルダへ移す（`ShellMoveToApplications`）
- App Translocation か読み取り専用のディスクイメージから開かれたら（Sparkle がアップデートを入れない場合と同じ）、`AppDelegate` が「Nonet をアプリケーションフォルダに移しますか？」と尋ねる。移す先は、すでに Nonet が入っているフォルダ（`/Applications` か `~/Applications`。2つ目を入れない。`ShellMoveToApplications.existingInstallDirectory`）、無ければ `/Applications`、そこに書き込めなければ（管理者でない）`~/Applications`。入っているフォルダに書き込めなければ、ほかへは入れずに移し方を伝える。どちらにも書き込めなければ、尋ねずに Finder でドラッグする方法を伝える
- 移す先にすでに Nonet があれば、置き換えてよいか確かめてから、古い方をゴミ箱に入れる。最後の入れ替えに失敗したら、ゴミ箱から元の場所に戻す
- 同じフォルダの隠した一時的な名前に写し、写しから `com.apple.quarantine` を外し（Finder で移したときと同じ。外さないと、移した先でまた App Translocation で開かれる）、入れ替える。写すのに失敗したら、写しかけのものも残さない
- 入れ替えたら、このプロセスが終わるのを待ってから移した先を開くよう頼み、自分は終わる

## 7. 実機で確かめられていないこと

フェーズ0の検証アプリでは手動テストが終わっていない。次の点は設定で切り替えられるようにし、既定値は安全側にする。
- ポインタの固定: 移動イベントを捨てて止まるか → `CursorLockMethod.automatic`（捨てたうえでずれたら戻す）に固定し、設定では選べない（ほかの方式はコードに残っている）
- 触覚: 別アプリが前面のとき `NSHapticFeedbackManager` が効くか → MTActuator を優先し、失敗したら公開 API
- 2本指スワイプが前面アプリ（Safari の戻るなど）に届かないか → セッション中はジェスチャー系のイベントも捨てる
- 「タップでクリック」のクリック（mouseDown）と、MultitouchSupport の指が離れたフレームのどちらが先に届くか（手動テスト T5 で、CGEvent / NSEvent のタイムスタンプを指のフレームと並べてログに出す）。0.2秒の猶予（`clickGraceInterval`）と 0.5秒の `lateClickWindow` で足りるか。本物の HID のイベントで CGEvent のタイムスタンプの単位が何か。タップが捨てた「押す」が `hidSystemState` のボタンの状態に表れるか（表れないと、捨てたボタンを忘れる見直しが早すぎたり遅すぎたりする）

- 上の縁から開く動き（§5 の 1）: 帯の奥 0.09・下へ 0.05・0.6秒・斜めまで（|dx| ≤ 1.5 × dy）で、ふだんの操作（上の縁の近くからポインタを動かす・スクロール・クリックしたままのドラッグ）で誤って開かず、狙えばすぐに開くか。開いたときにポインタを触れ始めた位置へ戻すのが目障りでないか。外枠（左右 0.11・手前 0.15・奥 0.17）がやめるのに狙いやすく、端のマスを狭くしすぎないか。離す前に留まる 0.1秒（`liftDwell`）と境界の帯 0.015 が、選んだつもりの実行を落とさず、通りかかっただけのマスを実行しないか。少し長く止める 0.45秒（`holdDwell`）が長すぎないか。左右の外枠に止めてページを切り替える 0.5秒・0.9秒（`edgePageDwell`・`edgePageRepeat`）が、やめるつもりで外枠に出たときに邪魔にならず、待つのがもどかしくないか（この数値は最初の実機テストで「開かないことがある・離しても実行されない・止める時間が長い・スワイプがやりづらい」となって直したもの）
- 手のひらの見分け（§5 の 1）: `EdgeSlideRecognizer.palmMajorAxis` = 25 は、MultitouchSupport の `majorAxis`（指先でおよそ 8〜15、平らに置いた親指で 20 ほど、という見込み）から決めた値で、実機では確かめていない。単位が見込みと違っても、手のひらを見分けなくなる方向にしか外れない（今より悪くはならない）。実機で指先・親指・手のひらの値をログに出して確かめる
- 2本指の後に滑らせ直す 0.02（`reselectTravel`）・マウスの見分け（指を離して 0.5秒）が実機で妥当か。離して 0.5秒より後に「タップでクリック」が届かないか。2打の触覚（50ms・40ms）が1打と区別できるか
- シェルを調べる `zsh -l -i`（§6「アクション」）: ~/.zshrc が ~/Documents などに触れると、macOS が Nonet の名前で許可を求めることがある。ショートカットの出力（`--output-type` を付けずに標準出力を読み、テキストなら結果のパネルに出し、リッチテキストは文字にし、画像などは出さない）は、実物のショートカットでは通して試していない（テキスト・画像を返すもの、何も返さないものでパネルの出方と失敗しないことを確かめる。[release.md](release.md) 4）

手動で確かめること（トラックパッドの開始し直し。§5「トラックパッド」）: スリープと復帰、外部ディスプレイをつないだまま蓋を閉じて開く、Magic Trackpad を外してつなぎ直す、ファストユーザスイッチ。どれも起動し直さずにトラックパッドが使え続けるか、ログの「トラックパッド（…）: N 台を開始」と開始し直しの記録を見る
